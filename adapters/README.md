# Observatory instrument adapters

These adapters connect real open-source SDKs. The default BrainFlow source is **synthetic**, and the default quantum backend is **Qiskit Aer simulation**. Neither default is a physical experiment.

## Install locally

Use Python 3.11 or later in an isolated environment:

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
```

## BrainFlow

```sh
python brainflow_bridge.py
```

Run the station locally using the source bundle's `pnpm dev`. In Instrument Dock, use `http://127.0.0.1:8768` and paste the session token printed by the adapter. The token stays in the page's memory and is not included in captures. Stop with Ctrl+C.

The bridge uses `observatory-stream/1`: source, device, unit, sample rate, channel names and timestamped channel vectors. GET `/v1/samples?since=TIMESTAMP` requires a bearer token. Acquisition is bounded to the most recent minute (at least 2,048 frames); each response contains at most 2,048 frames. The page keeps at most 10,000 frames. A disconnected client can therefore miss data; this is a live monitor, not a lossless clinical recorder.

For the private hosted station, add its exact origin:

```sh
python brainflow_bridge.py --allow-origin https://empirical-observatory.madmanmuzza.chatgpt.site
```

Some browsers restrict HTTPS pages accessing local HTTP devices. Use the local station if access is blocked. Do not disable browser security or expose this bridge to a network. It always binds to 127.0.0.1.

Playback accepts files in **BrainFlow's native recording format**, not Observatory JSON. Specify the original board type:

```sh
python brainflow_bridge.py --board-id -3 --file recording.csv --master-board -1
```

The example master board is BrainFlow's synthetic board. For real recordings substitute the original device's board ID. Playback timestamps are regenerated by BrainFlow and are not evidence of the original event time. The packet source is `recorded-signal` even when the original recording was synthetic; keep the original provenance separately.

An example for a connected OpenBCI Cyton serial device is:

```sh
python brainflow_bridge.py --board-id 0 --serial-port COM3 --enable-hardware
```

Verify the port and [BrainFlow device parameters](https://brainflow.readthedocs.io/en/stable/SupportedBoards.html) for your device. This CLI exposes serial parameters; other device families can require additional transport settings. Hardware acquisition is not tested on this release. RMS shows signal amplitude; it is not an attention or consciousness measurement. Stimulus/EEG clock synchronization and artifact handling must be added before research on their relationship.

## Quantum circuits

```sh
python quantum_beacon.py --state +i --basis Y --shots 1024
python quantum_beacon.py --reference --output qiskit-reference.json
```

Aer uses ideal circuits. The browser's default adds 0.12 depolarising noise; the cross-library test explicitly reconciles that difference. Seeded shot streams are library-specific and are not expected to have identical random counts across libraries.

IBM hardware submission is an optional, untested path. Install a compatible `qiskit-ibm-runtime` separately and configure your account through IBM's official instructions. The operator must name a backend and explicitly enable execution:

```sh
python quantum_beacon.py --execute-hardware --backend YOUR_BACKEND --shots 128
```

The output is a provider job ID, not a measurement. Jobs can queue and consume account allocation. Retrieve the result through the provider SDK and retain job/backend/calibration metadata. Hardware results are not imported as browser-simulator replays. [SamplerV2 documentation](https://quantum.cloud.ibm.com/docs/en/api/qiskit-ibm-runtime/sampler-v2).

## Verification

From this folder inside the full source checkout: `python -m unittest -v test_adapters.py`. The cross-library test expects `../public/research/quantum-reference.json`, included in the adapter download. The test suite acquires only BrainFlow synthetic data and runs only local Aer jobs. No hardware or cloud credentials are needed.
