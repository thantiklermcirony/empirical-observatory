# Constructed continuation diagnostic — protocol candidate

This is a no-LLM integration diagnostic using real, pinned third-party Python source. It is neither an upstream benchmark nor evidence of improved agent reasoning. No scored policy comparison has run. Humanize was excluded before this protocol because its Git archive requires generated build metadata; its archive and exclusion are retained. More-itertools replaces it.

Five projects each receive the same six constructed continuations: unchanged fresh evidence; unchanged evidence older than a fixed one-hour freshness threshold; an unrelated documentation edit; a one-line source regression; an added assertion fixture within a declared input directory; and a failed recheck followed by restoration of the original source. The latter must not silently revive an older passing receipt. Each episode starts independently from the pinned source and successful checks. Mutations are our constructed fixtures, not discovered upstream defects.

Each project has three executable checks: source-import provenance, one primary behavior and a second independent behavior. The behavior checks explicitly depend on the import check. All methods receive exactly the same commands, file/directory scopes, watched environment, runtime identity and prior attempts. Scopes are declared manually and conservatively. No method receives the mutation label, expected result, hidden import trace or complete dependency oracle.

Four policies are compared: rerun all requested checks and prerequisites; conventional content/dependency invalidation; fixed freshness (one hour, latest successful attempt and prerequisite identity, ignoring file changes); and Active Context's planner. Conventional invalidation independently fingerprints declared inputs and observes the latest attempt; it does not call the candidate inspector or planner. Execution/receipt storage is shared infrastructure, charged equally. There is one check per requested behavior claim, so the candidate is expected to tie conventional invalidation on selected checks.

An independent full rerun after decisions supplies observable assertion outcomes. Its results are not policy inputs. A passing current assertion is a bounded positive result; an ordinary assertion failure is a negative result; timeout, launch error or invalid execution is unresolved. Retain all outcomes and logs. Compare false-positive verification, unresolved decisions, agreement with the full rerun, selected/executed check counts and measured end-to-end seconds. One continuation decision per policy is scored. The one-hour evidence age is an explicit synthetic continuation clock shared by all policies, not a changed receipt timestamp.

Wrap each complete policy decision, execution and final status operation in a monotonic timer. Charge each policy the same measured initial capture cost; separately record continuation-only time and evaluation-only oracle cost. Declared `cost` is one unit per check and is not measured compute cost. Fixed policy-order rotations across episodes limit order bias; this small diagnostic cannot establish a stable microbenchmark speedup.

The proposed superiority gate requires zero false-positive verifications, no more unresolved or incorrect decisions than rerun-all, and at least 20% lower total measured cost than the cheapest equally correct conventional policy. Identical selected-check sets versus conventional invalidation automatically fail the superiority gate, regardless of timing noise. Report ties and losses. Construction, source selection and assertion preflight may be checked before freeze, but no final scored run occurs until the parent freezes source/config/protocol hashes and explicitly authorizes it. No tuning follows the final run; faults or timeouts are retained and any corrected run is separately versioned.

Limitations: only five pure-Python projects, 30 authored continuations, one environment, known declared dependencies, no remote state, no LLM, no hidden dependency discovery, no claim of broad agent gains. Package licenses and immutable source links are recorded alongside archive hashes.
